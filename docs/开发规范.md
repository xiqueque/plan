# 开发规范

> 版本：v0.1
> 说明：日志、版本控制、代码、测试、发布的统一规则。

## 1. 日志规范

- logs 文件夹每天一个文件，命名 `yyyy-MM-dd.md`，模板见 `logs/模板.md`
- 内容分三部分：今日完成、待办事项、问题与备注
- 每个开发日结束时必须更新；需求有变更时同步更新需求规格说明书

## 2. 版本控制（git）

- 每完成一个功能点或一个阶段，提交一次
- 提交信息格式：`阶段/功能：说明`（例如 `Phase 1：新增置顶功能`）
- 用户数据（app/data/）不纳入版本管理（已在 .gitignore 中排除）

## 3. 代码规范

- 文件、函数命名清晰，关键逻辑写注释
- 数据读写统一走存储模块，界面代码不直接改文件
- 统一 UTF-8 编码；界面文案统一为中文

## 4. 测试要求

- 每个阶段结束做自测清单：功能正常、数据不丢失、重启可用
- 涉及提醒、打包的改动，必须实测后再交付

## 5. 发布清单

- 打包前：清空测试数据、确认版本号、更新使用说明
- 交付物：可运行 exe、使用说明（含数据备份、更换音效方法）
